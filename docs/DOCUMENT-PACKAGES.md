# Contract packages

The intended workflow keeps a readable main agreement and ordered business annexes (DPA, NDA, SOW, SLA, pricing, policies and other labels). One deliberate signature must cover the exact presented package. Later changes may follow a new signature, explicit acknowledgement or agreed notice process; preserve the original signed package and link each amendment. The automatic participant negotiation/signature report remains mandatory and separate from preaccepted contractual terms.

## Implemented foundations

The V1 immutable manifest in internal/documentpackage commits the exact main and ordered annex metadata, actual source identities and exact PDF key/version/hash/bytes/pages. Its domain-separated legal commitment differs from the canonical JSON object's plain SHA256. Decode requires trusted ownership/revision and expected commitment. Format limits are16 annexes,64KiB canonical JSON and aggregate50MiB/500pages; these are not runtime admission or capacity guarantees.

Migration99 adds a separate draft package header and selected attachment records. It does not promote agreements into the legacy block-envelope wrapper. Every selected PDF/source pin is immutable; later source-document edits do not follow into the selection. Replacement means an explicit remove/select operation. Titles, business categories and order remain editable. Each successful membership mutation advances the header generation and the root document clock. Scoped mutation queries require the expected generation. Native adapters must lock actual root/new-source document IDs in global UUID order before package rows, reserve scalar/result storage and recheck current credentials/authority through commit. Direct trigger lock inversions refuse with NOWAIT.

The database checks tenant/source identity, current PDF pins, exact HTML review/materialization identity, selected-text/key/version shapes, at most16 ordinals, immutable pin updates and captured-evidence eligibility. Actual source validation, verified provider reads and parser-derived byte/page counts remain the owned adapter's responsibility. Stored byte/page declarations in database tests are synthetic. Package mutation REST/MCP adapters and sender attachment UI are implemented; see [the attachment API](DOCUMENT-ATTACHMENTS-API.md). Checkpoint423 qualifies the controlled negotiated main+DPA+NDA browser ceremony and exact downloaded artifacts, with synthetic authentication/storage/mail boundaries.

Legacy Send refuses a nonempty attachment set rather than omit selected terms. Empty/main-only sets retain legacy sealing behavior. Root topology/deletion changes cannot hide a nonempty set. An empty header can be explicitly removed from a soft-deleted draft. Destructive purge and shared-source reference queries include package roots/selected subjects/objects; ordinary draft authoring is not reclassified as signing evidence. Privacy fulfillment and recipient export defer to a separate attachment/source-history review. Occupied package tables block lossy migration rollback.

Migration100 adds append-only draft captures with exact canonical bytea, distinct legal/object hashes and normalized member inventories derived atomically from those stored bytes. Root clock, attachment generation, current main PDF/source/review tuple and ordered selected annex snapshots must match under root then package locks. Draft ordinal gaps normalize to contiguous capture positions. A persisted unique predecessor prevents competing branches even with an older repeatable-read snapshot. Capturing does not advance the editable root clock/generation; old captures retain their own pins after later edits or detach. Positive BIGINT revisions remain decimal strings in canonical JSON.

Fixed scalar historical headers precede payload/member allocation; payload reads bind all identities, hashes and byte length. The Go capture adapter strictly decodes canonical bytes, both hash domains and aggregate declarations. SQL validates semantic shape, hashes and inventory, but JSONB equivalence cannot prove Go canonical spelling or duplicate-key rejection. No raw JSONB reserialization is used as the stored authority. Capture history participates in purge/shared-object, privacy and recovery references, blocks empty-header disposal and lossy occupied rollback, and remains draft history rather than signing evidence.

The paired native source-read foundation now locks actual root and standalone-source M94 headers in global UUID order, preserves the physical root scope and privately binds complete measured readers to each actual subject. Its fixed staff policy independently applies original credential/role/sender, draft/evidence/privacy and expected-clock checks to both documents. Staged source validation explicitly requires exact reviewed HTML and current materialization; it creates no revision/Send authority. Native source/reader loans retain their original consumers and physical-session fences.

The storage PDF-read descriptor comes from an actual exact-version HEAD, refuses unversioned/reserved/empty/oversized observations, and retains the concrete client/tuple privately. A one-shot Core GET checks actual response version/length before one exact fixed-size allocation, verifies EOF and SHA and synchronously joins response Close. It supplies neither authorization nor a resource permit: the native application must reserve provider metadata before observation and bytes before GET. These primitive APIs do not themselves select attachments. The owned application adapters perform selection, source verification, admission and isolated-parser measurement; their configured-provider and capacity acceptance remains separate.

## Remaining integration

The owned application now connects draft/capture persistence, source/storage verification and resource admission to root-locked package Send, immutable sealing intent and recovery. Sender selection/preview, frozen recipient member delivery and explicit incorporation consent, signature/certificate binding, template membership, final publication/outbox and participant-report V2 are implemented. Checkpoint423 passes a real-renderer two-Send negotiation/revision/resend/two-party-signing journey and seven exact UI downloads; all32 PDF pages were rendered and inspected or mapped to exact duplicates. The report exposes the retained shared public history with declared scope and cutoff; unsupported event details remain explicitly unavailable, and it excludes private forensic preimages. Retention recovery must preserve the same immutable freeze. Remaining business variants, structured PDF proposal/remediation and configured signature/acknowledgement/agreed-notice amendment flows require their own acceptance. Never attribute an old signature to changed bytes.

Recovery inventory now includes selected exact object pins, but its existing final grouping is still per object key: distinct versions of one key are reported as a conflict. Version-aware recovery and a real two-version restore regression remain required. This fail-closed inventory result is not complete package recovery support. Preserve all7 completion/release groups, exact CI/managed merge gates and configured-service/salesperson acceptance.
