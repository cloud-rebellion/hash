# Owned renderer API boundary

The renderer build is versioned 8.36.0-hash.5. Its API and PDF-engine helpers come from Gotenberg v8.36.0 with the original MIT license and per-file provenance in each package's UPSTREAM.json. All renderer imports use the local package identities; module IDs, provider interfaces, flags, optional PDF validation and render-only engine selection remain compatible.

One configured server serves HTTP and TLS, reports bind/certificate failures synchronously, and refuses HTTP/1 Upgrade: h2c before the library can buffer that upgrade body. Ordinary HTTP/1, HTTP/2 prior knowledge and TLS/HTTP2 remain supported. Private route read/write deadline controls pass through the owned response gate.

The request registry owns the complete Echo invocation through middleware, handler, telemetry and checked cleanup. A hard timeout cancels processing and fences late writes while retaining the worker, its Echo context, workspace and multipart lease until physical return. Worker completion is a final channel close. Stop requires serving-goroutine, socket and admitted-worker retirement; a failed or panicking cleanup retains its lease and fails health. The HTTP2 library's transport-only callbacks are outside application-worker accounting.

Multipart admission has two shared leases and a 24 MiB complete encoded-entity cap before parsing. Staging includes preamble and epilogue under the original processing deadline, uses a private workspace/file, and is closed and removed before uploaded assets are named. Cached forms are refused and their resources adopted for cleanup. The original deadline timestamp is checked before and after reads even if the context timer callback has not yet been scheduled. Existing decoded/downloaded byte limits still apply. Asynchronous multipart execution is refused because no owned lease-transfer protocol is implemented.

Generated renderer attachments explicitly refuse Range requests before opening output; app/recipient artifact routes are unchanged. This avoids ServeContent's unjoined multi-range producer and gives each conversion one complete response. Optional downloadFrom remains disabled in the configured profile; its upstream per-entry transports do not have a qualified whole-lifecycle retirement boundary.

Response output is opened relative to the private workspace with os.Root and checked as a regular file. ZIP/input/output/staging closes and workspace/form removal are checked. Expected attachment bytes are checked against delivered bytes. Transmitted Content-Length is withheld so response EOF follows checked cleanup; an incomplete transfer or uncertain cleanup aborts the transport without appending a second error body. Static symlinks and out-of-root paths are refused. This does not promise protection from a trusted module concurrently replacing its own output with a special file.

Pinned Go1.26.9 HTTP1 request-body Close marks its body closed on every normal return, including input-drain errors. Only a server-marked HTTP1 body whose raw Close returned normally is classified that way, after the read gate joins. Arbitrary closer errors, panics and file/socket cleanup uncertainty remain quarantined. Sockets are tracked separately. Pinned x/net HTTP2 body Close normally returns nil.

This draft requires fresh source, race/lifecycle, HTTP/PDF/signing and image acceptance. Earlier hash.2/hash.3/hash.4 receipts retain their original source/image and do not qualify hash.4. Original failed startup/capacity experiments remain failed. No additional cleanup grace, production capacity claim, configured-service acceptance, managed CI, merge or release is implied.
